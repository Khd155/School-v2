# استعلام التحصيل الدراسي — الدراسات الإسلامية

منصة يستعلم منها أولياء الأمور عن تحصيل طلاب الصف السادس (الفصول 4 و5 و6) في مدرسة عبدالرحمن بن أبي بكر الابتدائية، ولوحة محمية يحدّث منها المعلم البيانات ومعلومات المدرسة.

## دليل المعلم

**1. الدخول**
افتح `/admin` وأدخل كلمة المرور الأولية التي ضُبطت في إعدادات الخادم (`ADMIN_PASSWORD`). بعد أول دخول غيّرها من صفحة «الحساب». تُقفل المحاولات مؤقتًا بعد 5 محاولات خاطئة.

**2. معلومات المدرسة والشعارات**
من «معلومات المدرسة» عبّئ إدارة التعليم، والعام والفصل الدراسي، واسم المعلم، ونص التذييل. ارفع شعار الوزارة وشعار المدرسة (PNG أو WebP أو SVG، حتى 1 ميجابايت). إذا لم تُرفع الشعارات يظهر الرأس نصيًا. هذه التعديلات لا تغيّر «آخر تحديث للبيانات».

**3. تحديث بيانات الطلاب**
من «بيانات الطلاب» ارفع ملف «الملخص العام.xlsx» ثم راجع المعاينة:
- **الأخطاء** (بريد مكرر، اسم أو بريد أو فصل مفقود، فصل غير مفعّل) تمنع الاعتماد. أصلحها في الملف وارفعه مجددًا.
- **التنبيهات** (مجموع لا يساوي تفاصيله، قيمة غير رقمية، حالة تسميع غير معروفة) لا تمنع الاعتماد، والقيم تُعتمد كما هي دون تعديل.

اضغط «اعتماد البيانات». تُحفظ النسخة السابقة ويمكن استرجاعها من «النسخ السابقة» (يُحتفظ بآخر 10 نسخ).

**4. رموز الوصول**
من «رموز الوصول» اضغط «توليد رموز للطلاب بلا رمز»، ثم فورًا «تنزيل CSV» أو «طباعة بطاقات التوزيع». الرموز محفوظة مشفّرة ولن تظهر مرة أخرى. إذا فقد ولي أمر رمزه استخدم «إعادة توليد» لذلك الطالب، فيتوقف رمزه القديم. تبقى الرموز صالحة عند تحديث البيانات ما دام البريد لم يتغير.

**5. مشاركة الرابط**
شارك رابط الصفحة الرئيسية مع أولياء الأمور، مع بطاقة كل طالب (البريد + الرمز). لا يرى أحد نتيجة طالب إلا بالبريد ورمزه معًا.

## الأمان باختصار

- كل البيانات والحسابات على الخادم؛ المتصفح يستلم تقرير الطالب الذي تم التحقق منه فقط.
- رموز الوصول وكلمة مرور المعلم محفوظة بـ scrypt مع salt.
- رسالة الخطأ واحدة سواء كان البريد غير موجود أو الرمز خاطئًا، والزمن متقارب في الحالتين.
- حد للمحاولات: 5 لكل بريد و30 لكل IP كل 15 دقيقة للاستعلام، و5 لكل IP لدخول المعلم.
- جلسات بكوكي `httpOnly` و`Secure` و`SameSite=Strict`. لوحة المعلم تتحقق من الأصل (Origin) ومن رمز CSRF وصلاحية الجلسة في كل عملية.
- جلسة ولي الأمر تنتهي بعد 30 دقيقة، أو فور إعادة توليد رمز الطالب.
- ملفات SVG تُنقّى من السكربتات والروابط الخارجية، ونوع كل ملف يُفحص من محتواه الفعلي.
- سياسة CSP صارمة بـ nonce.

## ما ليس مفعّلًا

- **رمز التحقق عبر البريد**: غير مفعّل، لعدم وجود خدمة إرسال بريد مهيأة. المنصة تعتمد رمز الوصول الفردي الذي يوزعه المعلم، ولا تعرض أي خيار لإرسال بريد.

## التشغيل

المتطلبات: Node 20+، وقاعدة PostgreSQL.

```bash
cp .env.example .env.local   # عبّئ DATABASE_URL و ADMIN_PASSWORD و SESSION_SECRET
npm install
npm run db:migrate
npm run dev
```

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | اتصال PostgreSQL. في Supabase استخدم رابط الـ pooler (Transaction، المنفذ 6543). |
| `ADMIN_PASSWORD` | كلمة مرور المعلم الأولية (12 حرفًا على الأقل). تُستخدم في أول دخول ثم تُحفظ مشفّرة. |
| `SESSION_SECRET` | مفتاح عشوائي (32 حرفًا أو أكثر) لتوقيع جلسات أولياء الأمور. |
| `CHROMIUM_PATH` | (للتطوير المحلي فقط) مسار Chromium لتوليد PDF. على Vercel يُستخدم `@sparticuz/chromium`. |

## الاختبارات

```bash
npm test                                  # اختبارات الاستيراد والحساب والتنسيق
node tests/make-fixtures.mjs              # يعيد توليد ملفات Excel التجريبية
BASE_URL=http://localhost:3000 DATABASE_URL=postgres://...localhost... \
ADMIN_PASSWORD=... CHROMIUM_PATH=... node tests/e2e/smoke.mjs
```

اختبار `smoke.mjs` يمسح قاعدة البيانات، لذلك يرفض العمل على أي قاعدة غير محلية.

## ملاحظات تقنية

- Next.js 15 (App Router)، و`postgres`، و`exceljs`، وPDF عبر Chromium بلا واجهة مع تضمين خط IBM Plex Sans Arabic في الملف.
- التقرير مكوّن واحد (`ReportDocument`) يُستخدم في الصفحة والطباعة وPDF، فتبقى الثلاثة متطابقة.
- المتوسط والأعلى يُحسبان لكل فصل من «المجموع النهائي» الرقمي فقط: الأصفار تدخل في الحساب، والفارغ وغير الرقمي يُستبعدان.
- الاعتماد والاسترجاع يجريان داخل transaction؛ إذا فشلت العملية تبقى البيانات السابقة منشورة.
