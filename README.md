# استعلام التحصيل الدراسي — الدراسات الإسلامية

منصة يستعلم منها أولياء الأمور عن تحصيل طلاب الصف السادس (الفصول 4 و5 و6) في مدرسة عبدالرحمن بن أبي بكر الابتدائية، ولوحة محمية يحدّث منها المعلم البيانات ومعلومات المدرسة.

## دليل المعلم

**1. الدخول**
افتح `/admin` وأدخل كلمة المرور الأولية التي ضُبطت في إعدادات الخادم (`ADMIN_PASSWORD`). بعد أول دخول غيّرها من صفحة «الحساب». تُقفل المحاولات مؤقتًا بعد 5 محاولات خاطئة.

**2. معلومات المدرسة والشعارات**
من «معلومات المدرسة» عبّئ إدارة التعليم، والعام والفصل الدراسي، واسم المعلم، ونص التذييل. ارفع شعار الوزارة وشعار المدرسة (PNG أو WebP أو SVG، حتى 1 ميجابايت). إذا لم تُرفع الشعارات يظهر الرأس نصيًا. هذه التعديلات لا تغيّر «آخر تحديث للبيانات».

**3. تحديث بيانات الطلاب**
من «بيانات الطلاب» ارفع ملف «الملخص العام.xlsx» ثم راجع المعاينة:
- **الأخطاء** (بريد مكرر، اسم أو بريد أو فصل مفقود، فصل غير مفعّل) تمنع الاعتماد. أصلحها في الملف وارفعه مجددًا.
- **التنبيهات** (مجموع لا يساوي تفاصيله، قيمة غير رقمية، حالة تسميع غير معروفة) لا تمنع الاعتماد، والقيم تُعتمد كما هي دون تعديل.

اضغط «اعتماد البيانات». تُحفظ النسخة السابقة ويمكن استرجاعها من «النسخ السابقة» (يُحتفظ بآخر 10 نسخ).

**4. رموز الوصول**
من «رموز الوصول» اضغط «توليد رموز للطلاب بلا رمز»، ثم فورًا «تنزيل CSV» أو «طباعة بطاقات التوزيع». الرموز محفوظة مشفّرة ولن تظهر مرة أخرى. إذا فقد ولي أمر رمزه استخدم «إعادة توليد» لذلك الطالب، فيتوقف رمزه القديم. تبقى الرموز صالحة عند تحديث البيانات ما دام البريد لم يتغير.

**تفعيل رمز الوصول أو إلغاؤه**
من «معلومات المدرسة» ← «الاستعلام» ← «طلب رمز الوصول مع البريد المدرسي». عند الإلغاء يكفي البريد لعرض التقرير، وتبقى المحاولات محدودة لكل IP. عند إعادة التفعيل تنتهي فورًا كل الجلسات التي فُتحت بدون رمز، وتعمل الرموز المولّدة سابقًا.

**سجل البحث**
من «سجل البحث» تظهر كل محاولة استعلام: الوقت، والبريد المُدخل، والطالب، والنتيجة (عُرض التقرير، بريد غير موجود، رمز خاطئ، لا توجد نتيجة، أُوقف لكثرة المحاولات)، مع ملخص آخر 24 ساعة، والاطّلاع حسب الفصل (من اطّلع ومن لم يطّلع)، والنشاط اليومي لآخر 14 يومًا، وزر «تنزيل CSV» للسجل كاملًا لعمل أي إحصائية في Excel. لا يُحفظ رمز الوصول ولا عنوان الجهاز، ويُحتفظ بآخر 5000 محاولة.

**5. مشاركة الرابط**
شارك رابط الصفحة الرئيسية مع أولياء الأمور، مع بطاقة كل طالب (البريد + الرمز). لا يرى أحد نتيجة طالب إلا بالبريد ورمزه معًا.

## الأمان باختصار

- كل البيانات والحسابات على الخادم؛ المتصفح يستلم تقرير الطالب الذي تم التحقق منه فقط.
- رموز الوصول محفوظة بـ HMAC-SHA256 مع مفتاح سري خارج قاعدة البيانات، وكلمة مرور المعلم بـ PBKDF2 مع salt ثم HMAC. اختيرت هذه الطريقة لتناسب حد المعالج في خطة Workers المجانية.
- رسالة الخطأ واحدة سواء كان البريد غير موجود أو الرمز خاطئًا، والعمل المنفّذ متطابق في الحالتين.
- رمز الوصول مفعّل افتراضيًا ويتحكم فيه المعلم. عند إلغائه يصبح البريد وحده كافيًا، أي أن من يعرف بريد طالب يرى تقريره.
- حد للمحاولات: 5 لكل بريد و30 لكل IP كل 15 دقيقة للاستعلام، و5 لكل IP لدخول المعلم.
- جلسات بكوكي `__Host-` و`httpOnly` و`Secure` و`SameSite=Strict`. لوحة المعلم تتحقق من الأصل (Origin) ومن رمز CSRF وصلاحية الجلسة في كل عملية.
- جلسة ولي الأمر تنتهي بعد 30 دقيقة، أو فور إعادة توليد رمز الطالب.
- ملفات SVG تُنقّى بقائمة سماح (HTMLRewriter)، ونوع كل ملف يُفحص من محتواه الفعلي.
- ملف Excel يُقرأ في متصفح المعلم ويُرسل جدول خلايا يتحقق منه الخادم كمدخل غير موثوق، فلا يستهلك الخادم وقت معالج في فك الملف.
- سياسة CSP صارمة: سكربتات من نفس الموقع فقط، بلا سكربتات مضمّنة.

## ما ليس مفعّلًا

- **رمز التحقق عبر البريد**: غير مفعّل، لعدم وجود خدمة إرسال بريد مهيأة. المنصة تعتمد رمز الوصول الفردي الذي يوزعه المعلم، ولا تعرض أي خيار لإرسال بريد.

## البنية

Cloudflare Workers (خطة مجانية) مع Hono للخادم والواجهات، وD1 لقاعدة البيانات، وBrowser Rendering لملف PDF مع تضمين خط IBM Plex Sans Arabic، وStatic Assets للخطوط والأنماط والسكربتات.

- `src/worker.tsx`: المسارات وترويسات الأمان.
- `src/server/`: قاعدة البيانات، والتحقق، والجلسات، والشعارات، وPDF.
- `src/shared/`: كود مشترك بين الخادم والمتصفح (قراءة Excel والتحقق منه، والتنسيق).
- `src/views/`: الواجهات (`hono/jsx`). التقرير مكوّن واحد (`ReportDocument`) يُستخدم في الصفحة والطباعة وPDF.
- `src/client/`: سكربتات المتصفح، تُبنى إلى `public/assets`.
- `migrations/`: مخطط D1.

## التشغيل محليًا

```bash
npm install
cp .dev.vars.example .dev.vars        # عبّئ القيم
npm run db:migrate:local
npm run dev                          # http://127.0.0.1:8787
```

## النشر

```bash
npx wrangler d1 create school-grades      # مرة واحدة، ثم ضع database_id في wrangler.jsonc
npm run db:migrate
npm run deploy
npx wrangler secret put ADMIN_PASSWORD    # 12 حرفًا على الأقل
npx wrangler secret put SESSION_SECRET    # openssl rand -base64 48
npx wrangler secret put HASH_PEPPER       # openssl rand -base64 48 — لا تغيّره بعد توزيع الرموز
```

| السر | الوصف |
|---|---|
| `ADMIN_PASSWORD` | كلمة مرور المعلم الأولية. تُستخدم في أول دخول ثم تُحفظ مشفّرة. |
| `SESSION_SECRET` | يوقّع جلسات أولياء الأمور. تغييره يُخرج الجميع فقط. |
| `HASH_PEPPER` | مفتاح تشفير رموز الوصول وكلمة المرور. **تغييره يُبطل جميع الرموز الموزعة.** |

## الاختبارات

```bash
npm test                                  # الاستيراد والحساب والتنسيق
npm run typecheck
node tests/make-fixtures.mjs              # يعيد توليد ملفات Excel التجريبية
# مع تشغيل npm run dev:
BASE_URL=http://127.0.0.1:8787 ADMIN_PASSWORD=... CHROMIUM_PATH=... SKIP_PDF=1 node tests/e2e/smoke.mjs
```

اختبار `smoke.mjs` يمسح قاعدة D1 **المحلية** فقط، ويرفض العمل على أي رابط غير محلي. توليد PDF يحتاج Browser Rendering، فيُختبر بعد النشر.

## ملاحظات

- المتوسط والأعلى يُحسبان لكل فصل من «المجموع النهائي» الرقمي فقط: الأصفار تدخل في الحساب، والفارغ وغير الرقمي يُستبعدان.
- الاعتماد والاسترجاع يجريان في عملية D1 واحدة ذرّية (batch)؛ إذا فشلت تبقى البيانات السابقة منشورة.
- حدود الخطة المجانية: 10ms معالج لكل طلب (الطلبات الدافئة تستهلك 1–7ms، وبدء التشغيل البارد قد يصل إلى ~20ms ويُقبل حاليًا)، و10 دقائق يوميًا لـ Browser Rendering (يكفي لمئات ملفات PDF). إذا تعذّر PDF يظهر للمستخدم بديل «طباعة التقرير» ثم «حفظ بتنسيق PDF».
